🧠 Conceito Básico: O que é raise?

Em Python, a palavra raise serve para lançar um alerta de erro voluntário. É como um árbitro de futebol apitando uma falta quando alguém comete uma irregularidade (por exemplo, deixar o arquivo de credenciais vazio).

2.3 Primeiro Contato com Exceções: O que é try / except e por que ele é vital?

Até agora, você estava acostumado a programar com variáveis locais e operações matemáticas. Quando algo dava errado no seu código — como tentar dividir um número por zero ou tentar acessar um índice que não existe em uma lista —, o Python interrompia a execução imediatamente e exibia aquele bloco gigante de texto vermelho no terminal chamado Traceback (Error).

No mundo real, quando conectamos nossos aplicativos a serviços externos como o Banco de Dados Supabase na Nuvem, nós NÃO podemos deixar o aplicativo simplesmente fechar na cara do usuário se a internet oscilar ou se uma senha estiver errada!

É para isso que existe o mecanismo de Tratamento de Exceções com as palavras mágicas try e except.

🎪 A Analogia do Trapezista e a Rede de Proteção:

  • O bloco try (Tentar): É o trapezista fazendo sua apresentação no ar. Você coloca dentro do try todas as linhas de código que você quer que o computador execute, mas que sabemos que têm risco de falhar (por exemplo: chamar a internet, salvar no banco, ler um arquivo do disco).
  • A Exceção (O escorregão): Se alguma linha dentro do try falhar por qualquer motivo imprevisto, o Python não deixa o programa quebrar. O erro é "lançado" no ar.
  • O bloco except (A rede de segurança): É a rede de proteção que apara o trapezista! Em vez do programa fechar bruscamente, o fluxo de execução salta diretamente para dentro do except, permitindo que você capture a mensagem de erro e tome uma atitude elegante (como exibir uma mensagem amigável na tela do Flet).

A Anatomia do Código: Como funciona na prática?

try:
    # 1. O Python TENTA executar este bloco arriscado:
    cliente = connect_supabase()
    resposta = cliente.table("tarefas").select("*").execute()
    print("Deu tudo certo! Dados carregados.")

except Exception as erro:
    # 2. Se qualquer erro acontecer lá em cima, o Python pula IMEDIATAMENTE para cá:
    print(f"Ops! Aconteceu um problema: {erro}")
    # O programa continua vivo e você pode avisar o usuário na tela!

Entendendo Cada Peça do Tratamento de Erros:

Comando Para que serve? Exemplo de Situação Real
try: Abre o bloco protegido. Diz ao Python: "Tente rodar essas linhas com atenção redobrada." Tentar abrir conexão com a URL do Supabase pela internet.
except: Define o que fazer caso ocorra uma falha dentro do bloco try. Evitar que a janela do Flet feche do nada se o computador estiver offline.
Exception as erro Exception é a classe mãe de todos os erros do Python. A palavra as erro cria uma variável temporária chamada erro que guarda a mensagem exata do que deu errado. Descobrir se o erro foi "Senha incorreta", "Tabela não encontrada" ou "Timeout de conexão".
raise erro Repassa o erro para frente caso você queira que outra camada (por exemplo, o Controller ou a View) fique sabendo do problema. O Model tenta salvar, dá erro de rede e ele avisa o Controller para pintar a tela de vermelho.

💡 Resumo para Lembrar Sempre:

O try / except não conserta a internet caída nem corrige uma senha digitada errada pelo aluno, mas ele salva o programa de um travamento fatal, dando a chance de explicar com calma na tela o que aconteceu e como resolver!

3.3 Entendendo o Objeto Cliente: Por que usar cliente.table().select() e não SQL Puro?

Se você já estudou banco de dados antes (como SQLite ou MySQL tradicional), deve estar acostumado a escrever comandos SQL diretamente em texto dentro de uma string do Python, como por exemplo: 

# O jeito tradicional com SQL puro (conectado a um banco local):
cursor.execute("SELECT * FROM tarefas WHERE concluida = False ORDER BY id ASC;")

Porém, no nosso arquivo sql_tarefa.py, você viu que escrevemos desta forma: 

# O jeito moderno com o cliente oficial do Supabase:
resposta = self.cliente.table(self.tabela).select("*").order("id").execute()

Essa diferença pode parecer estranha no início, mas ela existe por um motivo muito importante na arquitetura de sistemas modernos na internet!

🌐 O que é o Objeto cliente do Supabase?

O Supabase não está instalado no seu computador; ele está hospedado em servidores de nuvem do outro lado do mundo! Por motivos de segurança e desempenho, um banco de dados na nuvem não abre portas diretas de conexão SQL para qualquer aplicativo cliente (isso facilitaria ataques de hackers).

Em vez disso, o Supabase se comunica usando a tecnologia da Web: APIs REST e chamadas HTTP. O objeto cliente (gerado por create_client(url, key)) é como se fosse um "navegador invisível de altíssima velocidade". Ele pega os comandos que você digita em Python e os transforma em requisições de rede seguras e criptografadas para o servidor.

Por que usar essa sintaxe encadeada (Query Builder)?

O estilo cliente.table("tarefas").select("*").order("id").execute() é chamado no mercado de Query Builder (Construtor de Consultas Orientado a Objetos). Veja as vantagens:

Comando SQL Puro Equivalente no Cliente Supabase O que acontece por trás dos panos?
SELECT * FROM tarefas; cliente.table("tarefas").select("*").execute() O cliente faz uma requisição HTTP GET para o servidor e já devolve o resultado convertido em dicionários Python dentro de resposta.data!
SELECT * FROM tarefas WHERE id = 5; cliente.table("tarefas").select("*").eq("id", 5).execute() O método .eq("id", 5) significa Equal (igual a 5). Evita erros de digitação e aspas esquecidas na consulta.
INSERT INTO tarefas ... VALUES (...); cliente.table("tarefas").insert(dados).execute() Faz uma requisição HTTP POST enviando o dicionário Python diretamente, sem você precisar montar strings com vírgulas e parênteses.
UPDATE tarefas SET concluida = True WHERE id = 2; cliente.table("tarefas").update({"concluida": True}).eq("id", 2).execute() Faz uma requisição HTTP PATCH segura alterando apenas os campos informados.
DELETE FROM tarefas WHERE id = 3; cliente.table("tarefas").delete().eq("id", 3).execute() Faz uma requisição HTTP DELETE excluindo a linha informada.

🛡️ A Maior Vantagem: Proteção contra Injeção de SQL (SQL Injection)

Quando você monta comandos SQL concatenando textos (ex: "SELECT * FROM usuarios WHERE nome = '" + texto + "'"), se um usuário mal-intencionado digitar comandos SQL no campo de texto, ele pode apagar o seu banco inteiro!

Ao usar o método cliente.table().insert() e .eq(), a biblioteca trata e higieniza todas as entradas automaticamente. É a forma mais segura e recomendada por empresas para conectar interfaces a bancos na nuvem!

⚙️ E o que significa o .execute() no final de cada linha?

O cliente do Supabase permite que você vá "montando" a sua consulta em etapas (escolha a tabela, escolha as colunas com .select(), adicione filtros com .eq(), ordene com .order()). A consulta só viaja pela internet de verdade quando você coloca o .execute() no final! O .execute() é o botão de "Disparar / Enviar Pedido" da consulta.

💡 Por que separar o Model em dois arquivos?

O arquivo model_tarefa.py representa "o que é" uma tarefa (seus atributos). Já o arquivo sql_tarefa.py cuida de "como salvar" essa tarefa. Se um dia mudarmos de Supabase para MySQL ou SQLite, só precisamos alterar o arquivo SQL; a classe Tarefa continuará 100% idêntica!

5. A Camada de Controle: Pasta controllers/

O Controller é o cérebro que comanda toda a lógica de negócio. A tela (View) não tem permissão para falar diretamente com o banco de dados, e o banco (Model) não sabe desenhar botões. O Controller fica no meio do caminho intermediando tudo com segurança e clareza.

7. Resumo Final: Como Tudo se Encaixa no Fluxo de Vida

🔄 O Ciclo de Uma Ação do Usuário:

  1. O usuário digita "Estudar para prova" e clica no botão da tela (main.py / View).
  2. O clique dispara o método controller.adicionar_nova_tarefa() (Controller).
  3. O Controller valida o texto e cria um objeto Tarefa (Model).
  4. O Controller manda a classe SQL_Tarefa executar um INSERT no banco (Supabase na Nuvem).
  5. Com o ID retornado pelo banco, o Controller chama a fábrica criar_card_tarefa() que instancia uma TarefaComumCard com fundo azul e ícone (View com Herança).
  6. O card é inserido na coluna visual e desenhado na tela para o usuário!
