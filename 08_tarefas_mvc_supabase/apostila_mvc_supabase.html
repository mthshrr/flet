1. Apresentação: O Próximo Nível do Desenvolvedor

Nas aulas anteriores, você aprendeu a usar Classes e Herança para criar componentes visuais elegantes no Flet. O código da interface ficou muito mais limpo do que aquele código procedural do início!

No entanto, o nosso aplicativo ainda tinha duas grandes limitações que impediam que ele fosse um sistema profissional de verdade:

  1. Dados Voláteis: Quando você fechava a janela do Flet, todas as tarefas cadastradas sumiam, porque elas ficavam salvas apenas na memória RAM do computador.
  2. Falta de Separação de Responsabilidades: Se colocássemos os comandos de banco de dados diretamente dentro do arquivo da tela ou da classe visual, o código voltaria a ficar misturado e difícil de manter.

Neste material, nós resolvemos esses dois problemas de uma só vez utilizando o padrão mais famoso do mercado: a Arquitetura MVC conectada ao Banco de Dados Supabase (PostgreSQL na nuvem)!

2. O Padrão Arquitetural MVC (Model - View - Controller)

O padrão MVC divide o nosso software em três camadas fundamentais, onde cada arquivo tem um papel único e muito bem definido:

1. MODEL (Modelo)

models/

Cuida dos dados e do acesso ao banco. Representa a entidade Tarefa e executa os comandos SQL (SELECT, INSERT, UPDATE, DELETE). Não sabe nada sobre janelas ou botões do Flet.

2. VIEW (Visão)

views/ e main.py

Cuida da aparência e da interação com o usuário. Desenha a tela, os botões, caixas de texto e os cards com Herança. Captura cliques e repassa para o Controller.

3. CONTROLLER (Controlador)

controllers/

É o cérebro / maestro do sistema. Recebe os eventos da View, valida regras de negócio, chama os métodos do Model/SQL e manda a View atualizar a tela.

🏫 A Analogia do Restaurante:

  • A VIEW é o Cardápio e a Mesa: Onde o cliente (usuário) vê os pratos e escolhe o que quer.
  • O CONTROLLER é o Garçom: Ouve o pedido da mesa, confere se o pedido é válido e leva até a cozinha. Depois, traz o prato pronto para a mesa.
  • O MODEL é a Cozinha e a Despensa: Guarda os ingredientes (dados) e prepara a refeição (banco de dados). A despensa nunca fala direto com o cliente; tudo passa pelo garçom!

3.2 Criando a Tabela no Supabase (SQL Editor)

O Supabase é uma plataforma moderna que hospeda um banco de dados relacional PostgreSQL na nuvem. Para que nosso aplicativo funcione, precisamos criar a tabela tarefas. O arquivo database/schema.sql já vem com o script pronto: 

-- Execute este script no SQL Editor do painel do seu projeto Supabase:
CREATE TABLE IF NOT EXISTS tarefas (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome TEXT NOT NULL,
    tipo TEXT NOT NULL DEFAULT 'Comum',
    xp INT NOT NULL DEFAULT 10,
    concluida BOOLEAN NOT NULL DEFAULT FALSE,
    criado_em TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

ALTER TABLE tarefas ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Permitir acesso completo a tarefas" ON tarefas
    FOR ALL
    USING (true)
    WITH CHECK (true);

🔑 O Arquivo de Segredos: .env

Nunca coloque chaves de API ou senhas de banco diretamente dentro do código Python! Usamos o arquivo .env com a biblioteca python-dotenv. Basta criar um arquivo com o nome exato .env e colar suas credenciais: 
SUPABASE_URL=https://exemplo.supabase.co
SUPABASE_KEY=sua-chave-anon-aqui

4. Novo Conceito Fundamental: Tratamento de Exceções com try / except

Quando trabalhamos com banco de dados e serviços na nuvem, muitas coisas fora do nosso controle podem falhar: a internet do usuário pode cair, a senha pode estar errada ou a tabela pode não existir.

Sem tratamento de erros, o Python simplesmente trava e fecha a janela na cara do usuário com uma mensagem vermelha assustadora no terminal! Para evitar isso, usamos o bloco try / except: 

try:
    # Tente executar este código que pode falhar:
    cliente = connect_supabase()
    verificar_tabela_tarefas(cliente)
except Exception as erro:
    # Se der qualquer erro, o programa NÃO trava!
    # Ele pula para cá e podemos exibir uma tela amigável para o aluno:
    exibir_tela_erro_configuracao(page, str(erro))

🛡️ Regra Prática:

Toda operação de rede ou de banco de dados (consultar, salvar, deletar) deve ser envolvida em um bloco try / except para que seu sistema seja resiliente e confiável.

5. Análise Detalhada dos Arquivos do Projeto

5.1 O Modelo Puro de Dados: models/model_tarefa.py

Este arquivo define o que é uma Tarefa no sistema. Observe que ele não importa Flet nem Supabase. É uma classe pura de Python (POO): 

class Tarefa:
    def __init__(self, nome: str, tipo: str = "Comum", xp: int = 10, concluida: bool = False, id_tarefa: int = None):
        self.id = id_tarefa
        self.nome = nome
        self.tipo = tipo
        self.xp = xp
        self.concluida = concluida

    def alternar_conclusao(self):
        if self.concluida:
            self.concluida = False
        else:
            self.concluida = True

    def para_dicionario(self):
        dados = {"nome": self.nome, "tipo": self.tipo, "xp": self.xp, "concluida": self.concluida}
        if self.id is not None:
            dados["id"] = self.id
        return dados

    @staticmethod
    def de_dicionario(dados: dict):
        return Tarefa(
            id_tarefa=dados.get("id"),
            nome=dados.get("nome", ""),
            tipo=dados.get("tipo", "Comum"),
            xp=dados.get("xp", 10),
            concluida=dados.get("concluida", False),
        )

5.2 O Repositório de Acesso ao Banco: models/sql_tarefa.py

Aqui mora o CRUD. É este arquivo que fala com a tabela no Supabase:

  • listar_todas(): Faz .select("*").order("id") e transforma as linhas do banco em uma lista de objetos Tarefa usando um for tradicional e .append().
  • inserir(tarefa): Faz o .insert(...) dos dados da tarefa e preenche o tarefa.id gerado pelo banco.
  • atualizar_status(id, concluida): Faz o .update(...) filtrando com .eq("id", id).
  • excluir(id): Faz o .delete() filtrando com .eq("id", id).

5.3 A Camada Visual com Herança: views/ft_tarefa.py

Lembra do que aprendemos na aula anterior? Aqui reaproveitamos 100% da herança visual no Flet:

  • TarefaCard(ft.Container): Superclasse que define o checkbox, o texto com estilo tachado (LINE_THROUGH), o selo de XP e o botão de exclusão.
  • Subclasses Filhas:
    • TarefaComumCard: Fundo azul claro e ícone TASK_ALT (+10 XP);
    • TarefaUrgenteCard: Fundo vermelho claro e ícone WARNING_AMBER (+20 XP);
    • TarefaEpicaCard: Fundo dourado e ícone STAR (+50 XP).

5.4 O Maestro do Sistema: controllers/controle_tarefa.py

O Controller é a cola que une o Model e a View: 

class ControleTarefa:
    def __init__(self, page, sql_tarefa, coluna_tarefas, texto_xp):
        self.page = page
        self.sql = sql_tarefa
        self.coluna_tarefas = coluna_tarefas
        self.texto_xp = texto_xp
        self.xp_total = 0

    def adicionar_nova_tarefa(self, nome: str, tipo: str):
        # 1. Valida o nome
        if not nome: return False
        
        # 2. Cria o objeto Tarefa
        nova_tarefa = Tarefa(nome=nome, tipo=tipo, xp=xp, concluida=False)
        
        # 3. Salva no banco de dados na nuvem
        self.sql.inserir(nova_tarefa)
        
        # 4. Cria o card visual com a subclasse correta
        card = criar_card_tarefa(nova_tarefa, self.alternar_conclusao_tarefa, self.remover_tarefa)
        
        # 5. Adiciona na tela
        self.coluna_tarefas.controls.append(card)
        self.page.update()

Persistência Memória RAM (some ao fechar) Memória RAM (some ao fechar) PostgreSQL na Nuvem (Persistente para sempre)

7. Atividades Práticas para a Turma

Exercício 1: Teste de Persistência Real

Execute o arquivo main.py. Cadastre 3 tarefas (uma de cada tipo) e marque duas como concluídas. Em seguida, feche completamente a janela do Flet e rode o programa novamente. As tarefas continuaram lá com o XP somado corretamente? Parabéns, você domina bancos de dados na nuvem!

Exercício 2: Simulação de Queda de Internet (Testando o try/except)

Altere temporariamente a chave SUPABASE_KEY no seu arquivo .env para um valor qualquer errado. Execute o main.py e observe como o programa não trava: ele abre uma tela amigável explicando o checklist de correção! Depois de testar, volte a chave correta.

Exercício 3: Adicionando um Novo Campo no Sistema

Desafio profissional: adicione uma nova coluna categoria TEXT no banco de dados e ajuste o model_tarefa.py e o sql_tarefa.py para gravarem esse novo dado!
